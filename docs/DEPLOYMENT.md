# Deploying a BoringVault (runbook for engineers & agents)

How to deploy a full BoringVault system (vault + manager + accountant + teller + roles + withdraw queue) to
any EVM chain. The deploy is **config-driven**: you write two JSON files and run one script. Everything is
deployed deterministically via **CreateX (CREATE3)**, so addresses are a function of the deployer + a salt.

> TL;DR: fill a `deployment-config/<name>.json` + ensure `deployment-config/chains/<chainId>.json` exists →
> `make update-salts` → dry-run with `make checkL1 file=<name>.json` → broadcast with `make live-deployL1`
> (ledger) or the `--private-key` variant below.

---

## 1. What gets deployed (and in what order)

`script/deploy/deployAll.s.sol::run(string)` deploys, in order (see `_deploy`):
1. **BoringVault** (the share token + asset custody)
2. **FreezeListBeforeTransferHook** (skipped if you point the vault at `address(0)`)
3. **ManagerWithMerkleVerification**
4. **AccountantWithRateProviders** (+ rate providers from `01_DeployRateProviders`)
5. **Teller** (`TellerWithMultiAssetSupport`, or a cross-chain teller if configured) + **TellerSetup** (adds
   deposit/withdraw assets, wires the accountant)
6. **RolesAuthority** (+ all role grants)
7. **DistributorCodeDepositor** (only if `distributorCodeDepositor.deploy == true`)
8. **WithdrawQueue + fee module**

Addresses are written to `deployment-config/out.json` (copied from `out-template.json`) and, on broadcast,
moved to `outL1.json` / `outL2.json`; raw tx data lands in `broadcast/deployAll.s.sol/<chainId>/run-latest.json`.

---

## 2. Prerequisites

- **Foundry** (`forge`, `cast`) + **bun/node** (used by the salt + LZ-config helper scripts).
- A **funded deployer** on the target chain. Use a **throwaway key for testnets** — never a key holding real
  funds in a shared repo/env.
- **CreateX must exist on the chain.** The canonical CreateX `0xba5Ed099633D3B313e4D5F7bdc1305d3c28ba5Ed` is
  on most chains incl. mainnet & Sepolia. If a chain lacks it, deploy one first: `make setup-createx` (uses
  `script/DeployCustomCreatex.s.sol`). Set the address in `CREATEX`.
- **An Etherscan (v2) API key** for `--verify`.

### `.env` (copy from `.env.example`)
```
L1_RPC_URL=https://<your-rpc>          # the Makefile deploy targets read L1_RPC_URL / L2_RPC_URL
SEPOLIA_RPC_URL=https://<sepolia-rpc>  # also set this for Sepolia
PRIVATE_KEY=0x<throwaway-funded-deployer>   # only if using the --private-key path (not --ledger)
ETH_FROM=0x<deployer-address>
ETHERSCAN_API_KEY=<key>
CREATEX=0xba5Ed099633D3B313e4D5F7bdc1305d3c28ba5Ed
```
> For a Sepolia deploy, set `L1_RPC_URL` to your Sepolia RPC (the `*L1*` make targets use `L1_RPC_URL`).

## 3. The two config files

### 3a. Per-chain config — `deployment-config/chains/<chainId>.json` (REQUIRED, once per chain)
`getChainConfigFile()` (`script/Base.s.sol`) loads this by `block.chainid`. It holds chain-specific
addresses the deployer reads: `nativeWrapper`, `balancerVault`, `lzEndpoint`, `mailbox`,
`uniswapV3NonFungiblePositionManager`, and `assetToRateProviderAndPriceFeed.maxTimeFromLastUpdate`, etc.
Existing examples: `1.json` (mainnet), `8453.json` (base), `42220.json` (celo). **If your chain isn't there,
create it** (copy `1.json` and adjust). For a single-chain sandbox with no Balancer/LZ, zero-address the
unused ones but keep the keys present (the reader will `readAddress` them). `nativeWrapper` should be the
chain's WETH.

### 3b. Deployment config — `deployment-config/<name>.json` (one per vault)
Copy `deployment-config/exampleL1.json`. Fields:

| Field | Meaning |
|---|---|
| `nameEntropy` | CREATE3 salt seed — unique per deploy (drives all addresses). Bump via `make update-salts`. |
| `base` | The accountant's **base/denomination asset** (and usual first deposit asset). |
| `protocolAdmin` | Owner/admin of the system. |
| `boringVaultAndBaseDecimals` | Share + base decimals (match the base asset: 18 for most, 6 for USDC). |
| `boringVault.boringVaultName` / `boringVaultSymbol` | Share token name/symbol. |
| `boringVault.beforeTransferHookAddress` | Freeze hook, or `0x000…0` to disable. |
| `accountant.*` | `payoutAddress`, `allowedExchangeRateChangeUpper/Lower` (bps around 1e4), `minimumUpdateDelayInSeconds`, `managementFee`/`performanceFee` (bps, 1e4 = 100%). |
| `teller.*` | `tellerContractName`, `depositAssets[]` / `withdrawAssets[]` (+ per-asset fee arrays, same length), and LZ fields (`setupLZConfigs: false` to skip cross-chain). |
| `rolesAuthority.strategist` / `exchangeRateBot` | Curator (calls the manager) / the rate updater. |
| `distributorCodeDepositor.deploy` | `false` to skip the Nucleus deposit-gate. |
| `withdrawQueue.*` | `name`/`symbol`/`feeRecipient`/`minimumOrderSize`/`processorAddress`. |
| `*.address` fields | CREATE3-predicted addresses; regenerated by `make update-salts`. |

## 4. Deploy steps

```bash
# 0) one-time: ensure the per-chain config exists (deployment-config/chains/<chainId>.json) and CreateX is live
make setup-createx                      # only if the chain has no CreateX

# 1) fresh deterministic addresses (bumps salts in the config so you don't collide a prior deploy)
make update-salts files="<name>.json"

# 2) DRY RUN against a fork — the LiveDeploy test exercises the whole deploy + basic invariants
make checkL1 file=<name>.json           # runs test/LiveDeploy.t.sol on the fork
make deployL1 file=<name>.json          # simulates deployAll (no broadcast)

# 3) BROADCAST + VERIFY
#    a) hardware wallet (Makefile default):
make live-deployL1 file=<name>.json     # uses --ledger --broadcast --slow --verify

#    b) throwaway private key (sandbox/testnet) — run the script directly:
cp ./deployment-config/out-template.json ./deployment-config/out.json
LIVE_DEPLOY_READ_FILE_NAME=<name>.json \
  forge script script/deploy/deployAll.s.sol --sig "run(string)" <name>.json \
  --rpc-url $L1_RPC_URL --private-key $PRIVATE_KEY --broadcast --slow --verify
mv ./deployment-config/out.json ./deployment-config/outL1.json
```

Outputs: `deployment-config/outL1.json` (labeled addresses) + `broadcast/deployAll.s.sol/<chainId>/run-latest.json`.

## 5. Post-deploy wiring (what's NOT done by the script)

The script deploys + wires roles + adds the configured assets, but a usable vault still needs:
1. **Set the initial exchange rate** on the Accountant (the `exchangeRateBot`/rate role), if not 1:1 at init.
2. **Set the strategist's merkle root** on the Manager (`setManageRoot(strategist, root)`) — until then the
   vault can take deposits/withdrawals but run no strategies. Generate the root with the merkle-root tooling
   (see `docs/solana/merkle-root-*.md` for the leaf format) and the deployed decoder address.
3. **Unpause** the Teller if it deployed paused; confirm `depositAssets`/`withdrawAssets` are set (TellerSetup
   does this from the config).
4. **Grant any extra roles** (processor, freeze manager, additional strategists) via the RolesAuthority.
5. **Smoke test**: approve + `deposit` a small amount → check share balance → submit a WithdrawQueue order →
   `processOrders(1)` → confirm assets out.

## 6. Worked example — Sepolia sandbox (`tqWisdomSand`)

Target: **Sepolia, chainId 11155111**. Name `theoriq wisdomtree sepolia sandbox test`, symbol `tqWisdomSand`.
Owner = curator = one test address. Fees 0, no freeze hook, no cross-chain, WithdrawQueue on,
`distributorCodeDepositor.deploy=false`.

1. Create `deployment-config/chains/11155111.json` (copy `1.json`; set `nativeWrapper` = Sepolia WETH, zero
   the unused Balancer/LZ entries, keep all keys).
2. Create `deployment-config/tqWisdomSand.json` from `exampleL1.json`:
   - `base` = your Sepolia base asset (e.g. Sepolia USDC `0x1c7D4B196Cb0C7B01d743Fbc6116a902379C7238`, 6 dec) —
     or a mintable mock you deploy first.
   - `protocolAdmin` / `rolesAuthority.strategist` / `exchangeRateBot` / `accountant.payoutAddress` /
     `withdrawQueue.processorAddress` / `feeRecipient` = your test address.
   - `boringVaultAndBaseDecimals` = base decimals; `managementFee`/`performanceFee` = `0`;
     `beforeTransferHookAddress` = `0x000…0`; `teller.setupLZConfigs` = `false`;
     `depositAssets`/`withdrawAssets` = `[base]` with `[0]` fees; `distributorCodeDepositor.deploy` = `false`.
3. `make update-salts files="tqWisdomSand.json"`
4. `make checkL1 file=tqWisdomSand.json` (dry run; set `L1_RPC_URL` = Sepolia RPC)
5. Broadcast with the `--private-key` variant in §4(3b).
6. Post-deploy (§5): leave the merkle root empty (deposits/withdrawals work; no strategies yet).

## 7. Gotchas

- **Per-chain config must exist** for `block.chainid`, or the deploy reverts reading it. Sepolia needs
  `chains/11155111.json`.
- **Bump salts** (`make update-salts`) before a re-deploy on the same chain, or CREATE3 collides with the
  prior deployment's addresses.
- **CreateX prerequisite** — `make setup-createx` if the chain lacks it; set `CREATEX`.
- **The Makefile `live-deploy*` targets use `--ledger`.** For a key-based sandbox deploy, use the explicit
  `--private-key` command in §4(3b) (don't pass both).
- **`--slow`** is important on public testnets (sequential nonces) to avoid dropped txs.
- Fee bps are out of **1e4** (`managementFee: 2000` = 20%). Exchange-rate bounds are bps around 1e4.
- Verification: pass `--verify` with `ETHERSCAN_API_KEY` set; re-run with `forge verify-contract` if any
  contract misses.
- This deploys the **audited core** (base `ManagerWithMerkleVerification` + `GenericDecoderAndSanitizer`). The
  experimental pieces (`ManagerWithMerkleAndTokenBalanceVerification`, the next-gen `FullDecoderAndSanitizer`)
  are **not** wired into these scripts — add them deliberately, post-audit.
